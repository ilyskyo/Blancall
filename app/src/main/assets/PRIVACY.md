# Blancall 数据与隐私说明

> **本文档不是隐私政策，也不构成任何法律合规声明。**
>
> 它的唯一用途是：把 Blancall 的实际数据行为如实写清楚，方便你在自行编译、分发或二次开发时做出判断。
>
> 适用版本：v7.3.1（versionCode 46）

---

## 零、先说分发方式（这决定了一切）

Blancall 在 GitHub 上**只发布源代码，不发布任何安装包**。

| | 本项目提供 |
|---|---|
| 源代码（`.kt` / `.java` / `.gradle` 等） | ✅ |
| 编译好的安装包（`.apk` / `.aab`） | ❌ 不提供 |

想使用的人需要自行用 Android Studio 编译。

**这意味着什么**：软件本身不运行在你的设备上，因此它没有收集、传输、存储任何人个人信息的机会。数据处理发生在使用者自己编译、自己安装、自己运行的那个副本里 —— **那个人才是数据处理者**，义务也在他那边。

如果你日后改变了分发方式（发布 APK、上架应用商店、提供预编译下载），请重新评估本文档的适用性，并在应用内提供正式的隐私政策。

## 一、Blancall 的实际数据行为（如实描述）

### 1.1 无账号体系

不提供注册、登录、手机号、邮箱绑定。应用不存在"你的账号"这个概念。

### 1.2 无服务端

不部署服务器、不运营 API、不提供云同步。文章与学习数据只存在使用者自己的设备上。

### 1.3 声明的权限（共 3 个）

| 权限 | 用途 | 是否需要用户点击授权 |
|---|---|---|
| `POST_NOTIFICATIONS` | 每日学习提醒（本地通知） | 是（Android 13+，全应用唯一授权弹窗） |
| `VIBRATE` | 长按 / 拖拽的触感反馈 | 否 |
| `INTERNET` | **仅供可选的 AI 助手使用**，见 1.4 | 否（普通权限，安装即授予） |

**明确不申请**：存储、定位、相机、麦克风、通讯录、`QUERY_ALL_PACKAGES`、`FOREGROUND_SERVICE`、`SCHEDULE_EXACT_ALARM`、`RECEIVE_BOOT_COMPLETED`。

导入文章使用系统文件选择器（SAF），导出与分享通过 `FileProvider` 授予临时读权限 —— 因此**不需要任何存储权限**。

### 1.4 Pro 版（可选 AI）的网络行为

Blancall Pro 内置一个**默认关闭**的 AI 助手。开启它需要使用者**自己**填写 API 地址与密钥，本项目不提供、不运营任何 AI 服务。

**关键事实**：

- AI 请求从设备**直接发往使用者自己填写的那个地址**，中间没有任何第三方中转
- 开发者无法访问、查看或获取任何人的 API Key、对话内容或学习数据
- API Key 使用 Android Keystore 的 AES-256-GCM 加密后落盘，**明文永不写入磁盘**，应用进程无法导出密钥
- 请求时 Key 仅通过 `Authorization: Bearer` 请求头发送，不写入任何日志
- 三个 AI 开关（启用 AI / 保存对话 / 联网搜索）**默认全部为关闭**；关闭后所有 AI 入口从界面消失

### 1.5 不收集的信息

不收集设备标识（IMEI / OAID / MAC / Android ID / 型号）、不收集位置、不收集使用习惯或操作日志、无统计分析、无广告 SDK、无归因、无第三方 SDK。

应用会写入一个本地的 `crash.log`（记录未捕获异常，上限 256 KB），**该文件不会离开设备**，卸载即彻底删除。

### 1.6 系统云备份被显式关闭

`AndroidManifest.xml` 声明了 `allowBackup="true"`，但通过 `backup_rules.xml` 与 `data_extraction_rules.xml` **排除了整个数据目录**。

**原因**：跨设备的旧备份会把学习进度覆盖回早期状态。

**代价**：换机时无法通过系统云备份迁移，需要使用者自行处理。

## 二、两版差异对照

| | Blancall Std（标准版） | Blancall Pro |
|---|---|---|
| AI 模块 | **完全没有** —— 不是"关掉"，是"从未有过" | 可选，默认关闭 |
| `INTERNET` 权限 | **不声明** | 声明（仅 AI 用） |
| 与服务器通信 | 无 | 仅当使用者主动开启 AI 且自行填写地址 |
| 手写识别 | 有（7356 类 + 47 类，端侧离线推理） | 同左 |
| 背诵 / 记忆调度 / 统计 / 导出 | 完整 | 完整 |

标准版在**系统层面**即不具备联网能力。

## 三、手写识别模型

- 内置中文模型 **7356 类**（7185 汉字 + 171 字母数字符号）与拉丁模型 **47 类**
- 推理**完全在本地完成**，不联网、不上传墨迹
- 模型准确率的口径与限制，见 `assets/hccr/release_metadata.json` 的 `metrics_scope` 字段

**许可提示**：MIT 许可证覆盖本项目**源代码**，但**不覆盖**内置的手写识别模型权重文件 —— 因训练数据（CASIA-HWDB）授权限制，该权重仅供学习与研究用途，不得用于任何商业用途。详见 `THIRD-PARTY-LICENSES` 第 3 项。

## 四、微信小程序版（与上述两版不同）

小程序版**有**真实的个人信息处理，请单独对待：

- 微信登录（openid）
- 云同步（文章、标签、练习记录等核心学习数据）
- 文档与字体上传
- 签到与排行榜
- 匿名埋点（**不上报文章标题、正文、用户名、openid**）

因此小程序侧**已按平台要求**配有《用户协议》与《隐私政策》，并接入了隐私保护指引弹窗。若你使用小程序，请以小程序内展示的条款为准。

## 五、卸载与删除

- 应用内可手动删除文章、标签、对话记录、AI 配置等
- 卸载将清除设备上全部本地数据，**不可恢复**
- 通过导出功能保存到其他位置的文件副本不受影响
- 因为数据只在本地，**开发者无法远程为你删除或恢复任何内容**

## 附：为什么这份文档不叫"隐私政策"

如果它叫"隐私政策"，就会暗示"这是法定的隐私政策"，而实际上：

1. 本项目不运营任何服务、不收集任何数据，**不存在法律意义上的个人信息处理者**
2. 使用者编译运行的副本中，数据处理者是**使用者本人**，义务在其身上
3. 一份名不副实的"隐私政策"反而容易误导

所以它叫**数据与隐私说明**，定位是"如实描述技术事实"，而不是"法律合规文件"。

如果你日后要上架应用商店，那时需要的是一份真正的隐私政策（且内容要与你实际的行为一致），可以以本文档为基础改写。
